# 调研报告 — codex-with-chatgpt（上游）与本项目的关系

调研时间：2026-09-18。基于上游 XiaoDuoYa/codex-with-chatgpt v0.1.3（commit 9663b88）。

## 一句话结论

这是目前最完整的「网页订阅模型当大脑、本地 CLI agent 当手脚」开源实现：用**只读 MCP 桥（OAuth + 隧道 + 路径围栏）**做数据平面、**浏览器 DOM 自动化传递 [C2C] 微消息**做控制平面，把规划与审核外包给网页版 ChatGPT，执行权留在本地 agent。其桥接服务 agent 无关，可直接复用给 ZCode / Qoder / WorkBuddy。

## 仓库身份

- 本仓库 = 上游 XiaoDuoYa/codex-with-chatgpt 的 clone（popnie/codex-with-chatgpt 是上游的未改动 fork，5279 stars）。upstream remote 指向 XiaoDuoYa，可 fetch/merge 同步。
- TypeScript（Node ≥ 20）+ pnpm + vitest（146+ 测试），MIT 协议。官方声明为非官方社区项目，与 OpenAI 无关。
- 上游文档在本仓库 `docs/`：protocol.md（协议与消息格式）、architecture.md、security.md、troubleshooting.md。原 Codex 版 Skill 在 `skill/SKILL.md`（保留不动，供 Codex 用户）。

## 核心机制：双平面

```
网页版 ChatGPT（规划 + 独立审核）
   │ 控制平面：浏览器 DOM 自动化打字 [C2C] 状态消息（<1KB，只传状态不传内容）
   │ 数据平面：ChatGPT「连接器/开发者模式」（官方功能）经 Cloudflare 隧道 → 本地只读 MCP 桥
   ▼
本地桥 c2c（Express 仅绑 127.0.0.1 + OAuth 2.1/PKCE + 一次性配对码 + 9 个只读 MCP 工具）
   │ 只读
   ▼
本地工作区 ◄── 本地 agent 执行（编辑 / shell / git / 测试）
```

- **数据平面**：ChatGPT 网页连接器指向桥的公网隧道 URL，走 OAuth 2.1 + PKCE，模型自己拉代码行/diff/搜索结果，仓库不上传，不需要 OpenAI API Key。
- **控制平面**：agent 用浏览器自动化把 `[C2C]` 消息打进 ChatGPT 聊天框并轮询回复；唯一进浏览器的秘密是一次性配对码（5 分钟 TTL、5 次尝试、用后即毁）。

## 9 个只读 MCP 工具（src/mcp/server.ts）

workspace_info、list_directory、read_file（按行分页）、search_workspace（ripgrep）、git_status、git_diff（按字节分页）、test_status、execution_summary、execution_output（脱敏门控）。写/删/执行工具在服务端不存在——"只读 by construction"，prompt injection 也开不出来。

## 协议与状态机（docs/protocol.md）

```
INIT → PLAN → EXECUTING → EXECUTED → REVIEW → PLAN | DONE | BLOCKED
（HANDOFF：任务移交新对话；本地检查点状态不进 ChatGPT 消息；没有 STATE: RESUME，恢复靠 HANDOFF 简报）
```

- 规划者 = ChatGPT：收 INIT（仅 GOAL 一段话）后自己经 MCP 拉代码，产出 PLAN（GOAL/RATIONALE/ACTIONS/FILES_LIKELY_INVOLVED/TESTS/SUCCESS_CRITERIA），要求有限、具体、可执行。
- 执行者 = 本地 agent：用自己的 harness 执行；发 EXECUTED 前先 `c2c record` 写执行记录（元数据 + 可选脱敏命令输出）。
- 审核者 = ChatGPT：不信口头汇报，自己用 git_diff/read_file/test_status/execution_output 独立核查，再回 PLAN/DONE/BLOCKED。
- 循环上限 maxIterations（.c2c.json，默认 12）。

## c2c CLI（全部支持 --json）

serve(hidden)/start/stop/restart/setup/status/doctor/pair/unpair/logs/workspace/sandbox-allow/update-check/session(get|set|clear)/prefs(get|set)/record(hidden)/tunnel(status|choose|login)。
对用户项目执行的命令带 `-w <workspace>`；机器级命令（update-check、sandbox-allow、prefs、tunnel login）不带。

## 安全模型（docs/security.md + 实现）

- 只读 by construction；Admin API 仅回环 + admin token + 拒代理头。
- realpath 路径围栏（含最深存在祖先、大小写归一、防符号链接逃逸）、敏感文件 deny-by-default + `.c2cignore`。
- 执行输出脱敏：私钥硬拒整体拒绝；token/API key 正则 redact；截断 200 行 / 64KB。token 只存 SHA-256 哈希。
- 状态目录：Windows `%LOCALAPPDATA%\codex-with-chatgpt`（0700/0600），任何凭证不进项目目录。

## 首配流程（网页端，全部有固定 URL，不点菜单）

1. `c2c setup -w <ws>` → 返回 mcpUrl / pairingCode / workspaceName / connectorName
2. `https://chatgpt.com/#settings/Security` 开「开发人员模式」
3. `https://chatgpt.com/plugins#settings/Connectors?create-connector=true&redirectAfter=%2Fplugins` 建连接器：名称=connectorName、Server URL=mcpUrl、认证=OAuth → 授权 → 输配对码
4. 在会话里发 workspace_info 验证读到工作区名，通过才 `c2c session set` 存会话 URL
5. 隧道二选一：Quick Tunnel（临时地址，免账号）或 Named Tunnel（固定域名，需 Cloudflare 登录）

## 可复用 vs 需替换（对三端适配）

| 部分 | 结论 |
| --- | --- |
| 桥接服务（MCP+OAuth+配对+隧道）、协议、安全模型、执行记录 | agent 无关，原样复用 |
| `skill/SKILL.md` 工作流剧本 | 结构可复用，浏览器 API 与安装路径需按端改写 |
| Codex 内置浏览器 iab API | ZCode → browser-use（control-browser，能力等价）；Qoder/WorkBuddy → 手动中继降级 |
| `~/.codex/skills/` 安装路径、config.toml 沙箱 | ZCode → `~/.zcode/skills/`；sandbox-allow 保留（无 Codex 时仅创建白名单文件，保持 doctor 全绿） |
| 连接器名 / PRODUCT_NAME 常量 | v0.1.3 硬编码 "Codex with ChatGPT"（src/version.ts、src/config/endpoint.ts），已在本项目改为 "ChatGPT Brain"（差异清单见 docs/adapter-matrix.md） |
| cloudflared | 实现细节，TunnelProvider 已抽象；Windows 用 winget 安装 |

## 风险备忘

- chatgpt.com 改版会破坏页面定位 → 一律 DOM 快照定位，不写死选择器。
- 内置浏览器访问 chatgpt.com 可能遇 Cloudflare 人机验证 → 换浏览器后端或降级手动中继。
- 连接器是 ChatGPT 官方功能（需 Plus/Pro）；浏览器自动化属灰色地带，沿上游「非官方社区项目」声明。
